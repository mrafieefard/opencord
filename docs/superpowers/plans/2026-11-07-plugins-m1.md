# Plugins, Milestone 1: Runtime, Resource Manager and Bots — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Server admins can drop a plugin zip into Server settings → Plugins, review what it asks for, and run it. Its server scripts (Luau) act as a bot through the same checks as a member, react to every server event they may see, keep their own database and files, call allowed websites, answer web hooks and `/commands`. Developers get the `opencord-plugin` tool with signing and dev mode.

**Architecture:**
- **`opencord-plugins`** (new crate, MPL-2.0) holds what the server and the developer tool share: the Luau sandbox, package and manifest rules, signing, limits.
- **The server** runs one Luau VM per plugin on its own task. Each plugin acts through a **plugin user** (a `users` row nobody can sign in as) and a **managed role**, so every existing handler and permission check works for it unchanged. Gateway events reach plugins from the one fan-out point, `AppState::broadcast`, filtered by the plugin's permissions and what its role can see.
- **The apps** show plugin authors (desktop and phone) and give desktop admins the Plugins tab. Custom channels, activities and the client runtime are milestones 2–4; this plan doesn't start them.

**Tech Stack:** Rust 2024, axum 0.8, sqlx 0.9 (SQLite), prost, **mlua 0.11 with Luau** (new), **zip** (new), **semver** (new), ed25519-dalek 3, reqwest 0.13; Flutter with Riverpod 3 and flutter_rust_bridge 2.13; React Native with uniffi (Task 26 only).

**Spec:** `docs/superpowers/specs/2026-11-07-plugins-design.md`. Read all of it before Task 1, and the sections a task names before that task. "§" below means the spec. The spec says *what* and *why*; this plan says *where* and *how*. If they disagree, or a step can't be done as written, stop and ask the user.

## Review Focus

The inputs most likely to hurt real people while ordinary tests pass. Each has a pinned test in the task named.

1. **A plugin stuck in a loop or eating memory while people chat.** Expected: messages keep flowing, the plugin is restarted, then turned off with the reason on its page. Pinned in Task 7 (`an_endless_loop_does_not_delay_chat`, `a_plugin_that_keeps_failing_is_turned_off`).
2. **A hostile zip:** `..` paths, absolute paths, symlinks, case clashes, a zip bomb. Expected: refused with the rule broken, nothing written anywhere. Pinned in Task 2 (`stops_a_zip_bomb_while_reading`, `refuses_each_bad_path`) and Task 8 (`a_refused_zip_leaves_no_files`).
3. **A plugin reaching the server's own network:** a domain that resolves to `127.0.0.1` or `10.x`, `::ffff:127.0.0.1`, a redirect to a private address, DNS answers that change between checks. Expected: refused every time. Pinned in Task 10 (`a_name_resolving_to_a_private_address_is_refused`, `ipv4_mapped_loopback_is_refused`, `a_redirect_to_a_private_address_is_refused`, `each_connection_checks_the_address_again`).
4. **Events a plugin mustn't see:** messages in channels its role can't view; private messages, network and storage events even with every permission granted. Pinned in Task 9 (`a_hidden_channel_sends_the_plugin_nothing`, `off_limits_events_never_reach_a_plugin`).
5. **An update that fails to start, while the plugin is in use.** Expected: the old version comes back with its data, and the admin sees why the update failed. Pinned in Task 8 (`an_update_that_fails_to_start_rolls_back`).

# Stage A: Shared foundations

### Task 1: The Luau sandbox

**Owner:** Claude. **Score:** 5 (every plugin's code runs inside it).

**Files:**
- Create: `crates/opencord-plugins/Cargo.toml`, `src/lib.rs`, `src/limits.rs`, `src/sandbox.rs`
- Modify: root `Cargo.toml` (`[workspace.dependencies]`: `mlua`, `opencord-plugins`), `Cargo.lock`

**Interfaces:**
- Produces:
  - `pub const API_VERSION: u32 = 1;` in `lib.rs`; modules `limits`, `sandbox` (Tasks 2 and 3 add `package`, `manifest`, `permissions`, `signing`).
  - `limits.rs`: one `pub const` per row of the Global Constraints' limits that isn't config, named for what it limits (`PACKAGE_MAX_FILES`, `MANIFEST_TIME`, `EVENT_QUEUE`, `HTTP_TIMEOUT`, …), with `Duration`s and byte counts typed.
  - `pub struct VmLimits { pub memory_bytes: usize, pub handler_time: Duration }`
  - `pub struct Vm { pub lua: mlua::Lua, /* private budget */ }` with:
    - `pub fn new(limits: &VmLimits) -> Result<Vm, VmError>`: Luau, `lua.sandbox(true)`, memory limit, interrupt-based budget; globals as below.
    - `pub fn load(&self, chunk_name: &str, source: &str) -> Result<mlua::Function, VmError>`: text mode only.
    - `pub fn budget(&self) -> &Budget`.
  - `pub struct Budget` (cheap to clone, `Send + Sync`): `start(&self, limit: Duration)`, `pause(&self)`, `resume(&self)`, `stop(&self)`, `used(&self) -> Duration` (running time only), `total_used(&self) -> Duration` (since the VM was made, for CPU stats). The interrupt fails the running Lua with `VmError::BudgetExceeded` once running time since `start` exceeds the limit. Async host functions call `pause` before awaiting and `resume` after: `pub async fn paused<F: Future>(budget: &Budget, f: F) -> F::Output`.
  - `pub enum VmError { BudgetExceeded, OutOfMemory, Lua { message: String, traceback: Option<String> } }` with `impl From<mlua::Error>` classifying mlua's memory and interrupt errors, and `Display` giving the exact log texts: `"the handler ran longer than {ms} ms"`, `"the plugin ran out of memory"`, and the Lua message.
  - Globals a VM has: Luau's `string`, `table`, `math`, `utf8`, `bit32`, `buffer`, `coroutine`, `assert`, `error`, `ipairs`, `pairs`, `next`, `select`, `tonumber`, `tostring`, `type`, `typeof`, `pcall`, `xpcall`, `rawequal`, `rawget`, `rawset`, `rawlen`, `setmetatable`, `getmetatable`, `unpack`; `os` with only `time`, `clock` and `date`; `json` with `encode(value) -> string` and `decode(string) -> value` (`json.null` for JSON null); `print`, which calls a hook the host sets (`Vm::on_print(Box<dyn Fn(String) + Send + Sync>)`, default: dropped). **Not** present: `io`, `debug`, `loadstring`, `load`, `dofile`, `loadfile`, `getfenv`, `setfenv`, `require` (the runtime adds its own in Task 7), `collectgarbage` beyond `"count"`.
- Dependencies: `mlua` newest 0.11.x with features `luau`, `async`, `send`, `serde`; `serde_json` (workspace). Run the licence check (`luau0-src` is MIT).

-- Plugins (design 2026-11-07).

-- Plugin users: a users row nobody can sign in as (a random public key
-- with no private half), set for the plugin with this id. Kept after
-- uninstalling, so old messages keep their author.
ALTER TABLE users ADD COLUMN plugin_id TEXT;
CREATE UNIQUE INDEX users_by_plugin ON users (plugin_id) WHERE plugin_id IS NOT NULL;

-- A plugin's managed role.
ALTER TABLE roles ADD COLUMN plugin_id TEXT;

CREATE TABLE plugins (
    id TEXT PRIMARY KEY,
    user_id INTEGER NOT NULL UNIQUE REFERENCES users (id),
    role_id INTEGER NOT NULL UNIQUE REFERENCES roles (id),
    version TEXT NOT NULL,
    -- The installed version's folder name under data/plugins/<id>/.
    folder TEXT NOT NULL,
    -- The evaluated manifest, as JSON.
    manifest TEXT NOT NULL,
    signature TEXT NOT NULL CHECK (signature IN ('unsigned', 'signed', 'dev')),
    -- The pinned key (32 bytes) once a signed version was installed.
    public_key BLOB,
    github_check TEXT NOT NULL DEFAULT 'none'
        CHECK (github_check IN ('none', 'verified', 'mismatch', 'failed')),
    -- The admin's switch.
    running INTEGER NOT NULL,
    -- Set when it was turned off after failing; cleared when started.
    crashed_reason TEXT,
    license_accepted_by INTEGER REFERENCES users (id),
    installed_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL
);

CREATE TABLE plugin_permissions (
    plugin_id TEXT NOT NULL REFERENCES plugins (id) ON DELETE CASCADE,
    name TEXT NOT NULL,

### Task 27: The `opencord-plugin` tool

**Owner:** Gemini. **Score:** 3. **Review focus:** the private key never leaves its file; `pack` produces exactly what the server verifies; `dev` survives the server restarting.

**Files:** Create `crates/opencord-plugin-cli/` (`Cargo.toml` with `[[bin]] name = "opencord-plugin"`, MPL-2.0; `src/main.rs`, `src/{init,keys,pack,dev}.rs`, `templates/`, tests).

**Interfaces:**
- `opencord-plugin init <id>` → a folder `<id>/` with `manifest.lua` (id, name, version `0.1.0`, `api = 1`, `server = { "server/main.luau" }`), `server/main.luau` (logs on `start`), `opencord.d.luau` (copied from `crates/opencord-plugins/api/` at build time with `include_str!`), `.luaurc` pointing luau-lsp at the definitions, and `.gitignore`. Refuses a folder that exists.
- `opencord-plugin keygen [--out <path>]` → `~/.config/opencord-plugin/signing.key` by default (`dirs`-free: `$XDG_CONFIG_HOME` or `$HOME/.config`, `%APPDATA%` on Windows), printing the public key and its fingerprint.
- `opencord-plugin pack [<folder>] [--key <path>] [--out <file>]`: `Package::from_dir`; with a key, writes the key's `public_key` into `manifest.lua` (replacing an existing `public_key = "…"` line, or adding one after `version`), signs, and writes `<id>-<version>.zip`; prints the fingerprint. Without a key, writes an unsigned zip and says so.
- `opencord-plugin rotate-key --old <path> --new <path> [<folder>]` writes `KEY-ROTATION`.
- `opencord-plugin dev --server <host:port> --fingerprint <hex> --token <ocdev_…> [<folder>]`: zips the folder (unsigned) and `PUT`s it at start and on every change (polling the folder's files every 300 ms; no file-watching crate); prints **"Installed {version}, running"**, **"Waiting for an admin to review it on the Plugins page"**, or the error; streams the log with the long-poll and prints each line with its time and level; on connection errors retries every 2 s. The TLS check accepts the server whose certificate fingerprint is `--fingerprint` (`opencord_common::address::Fingerprint`), or a certificate trusted by the system.
