# Phone P1: You and Your Profile — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On the phone you can set your profile picture and status, tune your microphone and hear yourself test it, set the soundboard and voice sounds, and clear the attachment cache, as the desktop's user settings let you.

**Architecture:**
- **The You tab grows pages,** built with P0's settings kit: `Profile`, `Voice & audio`, `Sounds`, `Storage`, beside what's there (theme, music listening, backup).
- **The facade gains the core's avatar, audio, mic test, level meter and cue calls,** and maps the media events `InputLevel` and `NoiseSuppressionFellBack`, which it drops today (`crates/opencord-mobile/src/events.rs:628`).
- **The phone plays voice sounds for the first time.** The desktop decides which sound a change makes in Dart (`app/lib/core/providers/voice_cues.dart`, `cuesBetween`); the phone ports that pure function to TypeScript and plays each sound through the core's `play_cue`.

**Tech Stack:** as P0. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-15-phone-parity-design.md` §3 (P1, and "Not on the desktop either"), §6.2, §6.3. The desktop's pages are the reference for words and behaviour: `app/lib/features/settings/user/profile_pages.dart`, `app_pages.dart` (`VoicePage`, `_MediaCacheSection`), `sounds_page.dart`; `app/lib/core/rust/rust_repository.dart:383-420` (avatar) and `:1294-1316` (presence).

## Review Focus

1. **A server is offline when the picture changes.** Expected: it gets the new picture at its next Ready, as the desktop's `_catchUpAvatar`; a server that refuses (too large, its own limit) shows the server's error as a toast naming that server, and the others keep it. Pinned in Task 4: `a server that missed the picture gets it after Ready`, `one refusal names its server`.
2. **The microphone test while in a call, or a call joined during the test.** Expected: the test stops when a call starts (the desktop's `MicTestPanel` does), and the level meter stops sending when the page closes, so the phone isn't measuring in the background. Pinned in Task 5: `joining a call stops the test`, `leaving the page turns the meter off`.
3. **High noise suppression on a slow phone.** Expected: if the core falls back (`NoiseSuppressionFellBack`), the page shows `Standard` selected and the toast `High noise suppression is too heavy for this phone. Using Standard.` Pinned in Task 5: `a fallback moves the choice to Standard`.
4. **Voice sounds when the phone's own state changes several things at once** (joining a channel with people in it, a server mute while deafened). Expected: the same sounds in the same order as the desktop, none for others' changes when you're not in that channel. Pinned in Task 6: the table test ports every case of `app/test/unit/voice/voice_cues_test.dart`.
5. **Status after the app comes back from the background or reconnects.** Expected: the chosen status is sent again after every Ready, as the desktop's `_sendPresence` is; a choice made while offline holds. Pinned in Task 4: `status is sent again after Ready`.

### Task 2: Audio settings, the microphone test, the level and the voice sounds

**Files:** modify `crates/opencord-mobile/src/api/voice.rs`, `src/types.rs`, `src/events.rs`, `src/convert.rs`.

- `pub fn audio_settings_apply(settings: PhoneAudioSettings) -> Result<(), MobileError>`: builds the core's `AudioSettings` from the phone's three values and these fixed ones, which the phone doesn't offer: `input_device: None`, `output_device: None`, `push_to_talk: false`, `push_to_talk_release_ms: 0`, `automatic_sensitivity: true`, `echo_cancellation: true`, `automatic_gain: true`, `attenuation_percent: 0`, and every other field at the desktop's default (`AudioSettings` has no `Default`; copy the values `app/lib/core/settings/local_prefs.dart:273` gives a new install, through `audioSettingsTo` in `app/lib/core/rust/core_mapping.dart:808`, and name each in a comment). - `pub fn mic_test_set(on: bool)`, `pub fn level_meter_set(on: bool)`: `Client::set_mic_test`, `set_level_meter`.
- `pub fn cue_play(cue: VoiceCueKind, volume: f32)`, `enum VoiceCueKind { Join, Leave, UserJoin, UserLeave, Mute, Unmute, Deafen, Undeafen, StreamStart, StreamStop }`: `Client::play_cue`.
- `MobileEvent::InputLevel { dbfs: f32 }` and `MobileEvent::NoiseSuppressionFellBack` from the media events of the same names. Read `MediaEvent::InputLevel`'s fields before mapping; the event's rate is the core's (it already limits it).
- **On the phone the microphone may not be open outside a call.** Read how the core opens the input for `set_mic_test` (`crates/opencord-core/src/media.rs`). If it needs an audio session the phone hasn't activated, the JavaScript side activates it the way joining voice does (`mobile/src/features/voice/audioActivation.*.ts`) before turning the test on; say which in the ledger.
